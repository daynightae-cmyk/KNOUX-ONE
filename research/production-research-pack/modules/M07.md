## Shared UI pattern
Dashboard strip -> scope/preflight -> simple controls -> advanced drawer -> results -> evidence drawer -> history/restore where applicable.

## Security model
Typed allowlisted native calls, per-operation elevation, canonicalized targets, protected-resource guards, no arbitrary shell.

## Operation lifecycle
Preflight -> collect/preview -> review -> confirm mutation if any -> execute -> verify -> persist evidence.

## Testing
Unit/contract tests + Windows integration + permission/failure cases + runtime smoke evidence. Mutation services additionally require before/after and restore testing.

## Runtime verification
A green CI job is necessary but not sufficient. Each service must record Windows build, binary SHA, typed input, execution evidence and post-state.

## Implementation sequence
- Reuse shared engines first.
- Close any PARTIAL service before adding optional enhancements.
- Implement PLANNED services in dependency batches.
- Keep STATIC_VERIFIED services unchanged until runtime evidence or a concrete gap justifies a refactor.
